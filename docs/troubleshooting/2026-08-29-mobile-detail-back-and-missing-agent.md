# 会话详情返回没反应、看不到助手消息

## 现象

- 进入会话详情再点返回，按钮看起来没反应。
- Codex 会话里几乎看不到助手正文，只剩用户气泡或工具区。
- 打开历史较长的会话时，整页会停住一段时间。
- 打开 Pi 会话后聊天区完全空白，标题却显示这条会话的主题。

## 根因

这不是三个互不相关的按钮/过滤 bug，而是同一条远程数据面：

1. **首包过大**：`session.watch` 曾把整份历史一次送上手机。本机当时 527 个会话的首包合计约 101 MB，最大单会话约 1.87 MB。解密和 JSON 解码发生在主界面线程，返回按钮会像失灵。
2. **助手正文在开发机侧被漏掉**：Codex 当前记录是 `type=message, role=assistant, content=output_text`。旧解析器只认 `agent_message`，手机端根本收不到正文。不要把「客户端只显示 user/assistant」误判成过滤掉了助手——规范化之后助手角色就是 `assistant`。
3. **Pi 等助手未进入远程解析表**：桌面预览走扫描器，手机详情走另一张表。Pi 曾完全未登记，打开详情只能拿到空窗口。不要把空白当成「这条 Pi 没有对话」。
4. **详情页导航值绑在会刷新的列表行上**：会话列表的实时更新会换掉正在展示的那一行；再叠上整页左右滑的分页容器，系统返回手势会被抢走。

压缩只能减少线路字节。它不能替代「只传当前窗口」「按序号补增量」或「历史解析与控制请求隔离」。完整目标架构见 `https://github.com/corral-dev/corral/blob/main/docs/design/MOBILE_REMOTE_DATA_PLANE_DESIGN.md`。

## 已落地的止血

- 历史首包改为受限窗口，更早记录用「在此序号之前」继续取。
- 加密前对超过约 1 KB 的结构化载荷做 zlib 包装压缩；旧客户端不声明能力则仍走裸 JSON。
- Codex 同时识别旧 `agent_message` 与当前 `message/assistant/output_text`。
- Pi 已挂到远程纯文本解析；改解析器后抬高规范化缓存版本，并重启常驻远程服务。
- 聊天区在加载完成且没有用户/助手消息时显示空状态，不再留一片空白。
- 详情页用会话稳定标识做导航，不再让列表刷新拆掉返回栈；对话/终端切换不再占用系统返回手势。

## 禁止的误修

- 不要只把手机端超时从 20 秒改大。
- 不要为了让返回按钮能动，去禁止会话列表实时更新。
- 不要在手机端用固定字符串黑名单识别「这是不是助手消息」；运行时格式变化后会再丢一次。
- 不要因为桌面预览有内容，就认定手机空白一定是客户端过滤或「这条会话本来没消息」。先核对该助手是否已进入远程解析表。
- 不要把「单元测试通过 / 应用能启动」写成这条链路已修好；必须在同一台真机上走通：列表 → 打开有助手正文的会话（含 Codex 与 Pi）→ 点返回回到列表。

## 验收时必须核对的版本事实

- 开发机常驻远程服务的启动时间，以及它是否加载了带消息窗口和 Codex 新格式的源码/安装副本。
- 手机上 `com.x0c.corral` 的市场版本与构建号。
- 当前连接走局域网还是中继。
