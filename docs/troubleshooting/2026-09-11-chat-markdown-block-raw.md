# Chat markdown shows raw markers

## 现象

对话气泡里助手回复仍能看见 Markdown 原文：`### 标题`、`- 列表项`、`| 列 | 列 |` 与 `|---|` 分隔行，而不是标题字重、项目符号与可读表格行。加粗等行内语法可能仍正常。

## 根因

`ChatMarkdown` 曾用 `AttributedString.MarkdownParsingOptions.interpretedSyntax = .inlineOnlyPreservingWhitespace`。该模式只解释行内属性，块级标记原样保留。

若改成 `.full` 却不把 `presentationIntent` 落成换行/项目符号/表格分隔，块标记会被剥掉，但各块会粘成一行，同样不可读。`UITextView` 不会自动把语义意图画成可见排版。

## 修复

- `ChatMarkdown` 使用完整语法解析，并把块级意图落成可见结构（换行、`•`/序号、表格单元格用 ` | ` 分行、标题加粗略放大等）。
- 继续保留体积上限与 `NSCache`；展示层按会话字号缩放已烘焙字号。
- 单测覆盖「标题 + 列表 + 表格」不得再出现 `###` / `|---|`，且必须有多行与项目符号。

## 禁止的误修

- 不要为「更全语法」引入第三方 Markdown 库却仍在 SwiftUI `body` 无界同步解析。
- 不要退回 `.inlineOnly*` 假装修了 watchdog。
- 不要只改解析选项却不落结构样式。

## 验收

打开含标题、列表、表格的助手回复：看不见 `###` / 原始 `- ` 标记 / 表格管道草稿；标题更醒目，列表有项目符号，表格按行可读。装完回读市场版本与构建号。
