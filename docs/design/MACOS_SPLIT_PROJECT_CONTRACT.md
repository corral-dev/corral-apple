# Split project consistency

Owner decision (2026-10-14): every agent session shown together in one split works in the same project. The split's agent project comes from an agent already in the split, not from whichever pane currently has keyboard focus; a focused project terminal must not redirect a new agent to another folder. A quick assistant action in Add Pane creates its session in that project. When no agent is present, the focused terminal's project may start the first agent.

The Add Pane menu no longer offers **New Session in Split…**; the former Command-D sheet route is removed with it. This supersedes the Command-D row in the broader Mac client design while that document is being edited by another task. A normal New Session remains free to choose any project and opens separately. Opening an existing session in a split is available only when its project matches the split's agent project. If a create or handoff result has another project, show it as a separate session instead of mixing projects in the split. Do not relabel a split's project to match an incoming session.

Project identity is the host working-directory path, ignoring redundant trailing slashes. An empty working directory is an identity of its own; no basename-only match is sufficient. The host layout remains shared with the TUI, whose multi-selection grouping follows the same agent-project rule. iPhone has no session split.

The host rejects layout writes when scanned member projects disagree with each other or with the submitted group project. A session the scanner has not yet discovered does not block a new layout write; the Mac checks its own known session metadata before sending the write.

Existing host layouts can contain historical mixed-project groups. Opening such a group on the Mac shows only members matching its focused agent, or its first visible agent when focus is unavailable; restoring local panes also filters other-project agents. The TUI resolves a stored group using the selected agent's project and shows only matching members. Browsing a legacy group does not silently rewrite its stored membership; the excluded agent remains available as a separate session. A read-only scan on 2026-10-14 found one mixed group among groups whose member projects were available, with some historical members unresolved. This does not prove every stored group is clean.

Acceptance: with project A's agent and a focused project B terminal in one Mac split, quick Add Pane creates in A; Add Pane has no New Session in Split entry; a project B session cannot join A's split through the sidebar; A sessions can. Inspect the opened Mac window and the host layout/session values. TUI multi-selection with mixed A/B projects must not create a group; same-project selection can. A stored mixed group must not display mixed panes when opened or restored.
