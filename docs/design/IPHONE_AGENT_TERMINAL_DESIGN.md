## Inspected references and applicability

### Touch scrolling and selection (owner decision, 2026-10-21)

An ordinary one-finger vertical drag scrolls terminal content. It must not begin a text selection, focus the keyboard, or synthesize Up/Down keys that can change the input draft/history. Normal-buffer history retains the native scroll view's tracking and inertia. When the foreground writable agent requests mouse reporting, translate the drag and its bounded momentum into genuine terminal wheel events, never mouse-button press/drag events. A fullscreen application without mouse reporting cannot expose overwritten history through local scrollback; do not invent an arrow-key fallback.

Long-pressing text explicitly starts the existing local word/expression selection and Copy menu. Selection handles extend the selection, including the component's edge scrolling. Copy or a tap outside the selection clears it and restores scrolling. Selection is transient: hiding/leaving the terminal clears it. Reading above the live edge remains stable during incoming output, and reaching the bottom resumes following it. Add no persistent interaction preference or mode control. Apply the same touch policy to the iPhone project terminal, which uses the same UIKit component. This is Corral client input/presentation ownership, not SessKit parsing.

Inspected component references: `ShellTerminalHost` and SwiftTerm 1.20.0's [UIKit gestures](https://github.com/migueldeicaza/SwiftTerm/blob/5d14406844143538cd8f8851d2d8a67c1fe443e5/Sources/SwiftTerm/iOS/iOSTerminalView.swift) and [Mac wheel handling](https://github.com/migueldeicaza/SwiftTerm/blob/5d14406844143538cd8f8851d2d8a67c1fe443e5/Sources/SwiftTerm/Mac/MacTerminalView.swift). Reuse its native `UIScrollView`, local selection, handles, Copy and terminal wheel encoder. Reuse the Mac wheel's encoding/line accumulation, without its alternate-screen arrow fallback. Keep mouse clicks separate from scrolling.

## Chat-to-terminal bottom-gap fix (2026-10-15)

Owner report: switching an agent session from Chat to Terminal left a composer-height blank strip at the bottom that filled a moment later. Root cause: the iPhone composer is a bottom `safeAreaInset` (`ChatScreen`), so revealing the terminal grows its viewport by the composer height in the same transaction. `ShellTerminalHost` voted on every layout pass, so the host attached at the pre-expansion grid and only reached the settled grid after a second resize round-trip. Fix (iOS-only, `iOS/Views/Terminal/ShellTerminalView.swift`): coalesce fit votes with a 150 ms settle (matching the shared stream's resize settle) plus a last-vote dedup, so the first attach uses the settled grid; a retained emulator keeps its old screen while the fresh snapshot is on the way. Cross-end: Mac panes keep the same body size in both modes (the composer lives inside the chat view) and already dedup plus 150 ms-debounce, so the defect does not reproduce there; the TUI has no chat/terminal switch.
