## Inspected references and applicability

### Touch scrolling and selection (owner decision, 2026-10-21)

An ordinary one-finger vertical drag scrolls terminal content. It must not begin a text selection, focus the keyboard, or synthesize Up/Down keys that can change the input draft/history. Normal-buffer history retains the native scroll view's tracking and inertia. When the foreground writable agent requests mouse reporting, translate the drag and its bounded momentum into genuine terminal wheel events, never mouse-button press/drag events. A fullscreen application without mouse reporting cannot expose overwritten history through local scrollback; do not invent an arrow-key fallback.

Long-pressing text explicitly starts the existing local word/expression selection and Copy menu. Selection handles extend the selection, including the component's edge scrolling. Copy or a tap outside the selection clears it and restores scrolling. Selection is transient: hiding/leaving the terminal clears it. Reading above the live edge remains stable during incoming output, and reaching the bottom resumes following it. Add no persistent interaction preference or mode control. Apply the same touch policy to the iPhone project terminal, which uses the same UIKit component. This is Corral client input/presentation ownership, not SessKit parsing.

Inspected component references: `ShellTerminalHost` and SwiftTerm 1.20.0's [UIKit gestures](https://github.com/migueldeicaza/SwiftTerm/blob/5d14406844143538cd8f8851d2d8a67c1fe443e5/Sources/SwiftTerm/iOS/iOSTerminalView.swift) and [Mac wheel handling](https://github.com/migueldeicaza/SwiftTerm/blob/5d14406844143538cd8f8851d2d8a67c1fe443e5/Sources/SwiftTerm/Mac/MacTerminalView.swift). ## Chat-to-terminal bottom-gap fix (2026-10-15)

Owner report: switching an agent session from Chat to Terminal left a composer-height blank strip at the bottom that filled a moment later. Root cause: the iPhone composer is a bottom `safeAreaInset` (`ChatScreen`), so revealing the terminal grows its viewport by the composer height in the same transaction. `ShellTerminalHost` voted on every layout pass, so the host attached at the pre-expansion grid and only reached the settled grid after a second resize round-trip. Fix (iOS-only, `iOS/Views/Terminal/ShellTerminalView.swift`): coalesce fit votes with a 150 ms settle (matching the shared stream's resize settle) plus a last-vote dedup, so the first attach uses the settled grid; a retained emulator keeps its old screen while the fresh snapshot is on the way. Cross-end: Mac panes keep the same body size in both modes (the composer lives inside the chat view) and already dedup plus 150 ms-debounce, so the defect does not reproduce there; the TUI has no chat/terminal switch.

## Per-session remembered display mode (owner request, 2026-11-22)

Each mobile session remembers its last user-chosen display mode (`chat` or `terminal`), scoped by `(hostID, canonicalSessionKey)` in `SessionDetailModeStore` (`UserDefaults` keys `corral.ios.sessionDetailModes` and `corral.ios.sessionDetailModesOrder`, bounded LRU cap `500`, modeled on `MacSessionPresentationPreferences`).

- **Persistence scope:** remembered choices survive back navigation, switching sessions, client reconnects (`ObjectIdentifier(store)` rebuilds), notification-tap reopens, and app relaunches. Unseen sessions default to `.chat`.
- **Explicit switches only:** only deliberate user mode choices (detail More menu toggle, iPadOS `⌘E`, or session-list context menu switch) persist. Temporary absence of `terminalStream` capability while offline or cold-start connecting falls back visually to Chat View without overwriting the saved `.terminal` preference, and engages Agent Terminal automatically once `terminalStream` becomes available.
- **Debug inspection guard:** Debug `-CorralInspect*` / `CORRAL_INSPECTION_*` launches do not overwrite persisted user choices.
- **Lifecycle, aliases, and cleanup:** provisional-to-canonical session key promotions (`onSessionMigrated`, notification `session.get` resolution, and cached/list alias reconciliation) migrate the provisional mode without overwriting an explicit choice already stored on the canonical key. Deleting a session or unpairing a host (`HostStore.removeHost`) removes its stored entries.
- **List context menu parity:** `SessionListItem` uses the shared `SessionMenuItems.displayMode` path so each row's context menu dynamically reflects its remembered mode (`Switch to Chat View` when remembered mode is `.terminal`, `Switch to Agent Terminal` otherwise), persists the selection, and opens directly into that mode.
- **Cross-end boundary:** native Mac already persists per-session pane mode via `MacSessionPresentationPreferences`; CLI TUI has no Chat View vs Agent Terminal switch.

## Long-lived mobile terminals and instant return (owner report, 2026-11-23)

Owner report on iPhone `1.0.223 (237)`: returning to the session list and re-opening a remembered Agent Terminal session hung permanently on `连接中...` with `[]` instead of revealing the terminal immediately, and returning to an opened session must never trigger a reconnect.

- **Root cause (flight recorder `client-3724`):** 11/11 consecutive session opens recorded `orphanResponse` and **zero `terminal.attach` events**. Two compounding mechanisms caused this:
  1. `NavigationSplitView` compact push relocation transiently unmounted `AgentTerminalPane` right as a remembered-`.terminal` session opened, firing `.onDisappear -> stream?.stop()`, which set `stream.events = nil` while `@State private var stream` remained non-nil on the relocated view with an unchanged `ConnectionKey`; `.task(id:)` never restarted the stream and `deliverFit()` stayed a silent no-op.
  2. Tearing down `ShellTerminalHost` and sending `terminal.detach` on Back navigation or session switching destroyed the live screen and forced a full re-attach round trip.
- **Adopted contract (mirrors Mac `MacTerminalSessions` + `TerminalSlot`):**
  - `SessionSplitView` owns one host-scoped `MobileTerminalSessions` pool (`capacity = 16`, evicting least-recently-shown hidden terminals first and never evicting an on-screen terminal).
  - `RetainedShellTerminalView` + `ShellTerminalSlot` re-parent each session's `ShellTerminalHost` and live `RemoteTerminalStream` across Back navigation, session switching, Chat ↔ Terminal toggles, and `NavigationSplitView` relocation without calling `stream.stop()`.
  - Hidden terminals keep `isInFront = false` (`active: false` size-vote policy, keyboard resigned, hit-testing/accessibility disabled, touch reset) while quietly receiving live output.
  - Returning to a session re-parents its retained `ShellTerminalHost` on frame 0 with zero `terminal.detach`, zero `terminal.attach`, zero `连接中...` overlay, immediate cached background color propagation, and `stream.claimSize()`. `ShellTerminalHost.scheduleFit()` schedules `deliverFit` in `.common` RunLoop modes so navigation/scroll tracking never blocks cold-open fit delivery.
  - Streams close only on session deletion, host switch (`reset()`), LRU eviction above 16, or explicit replacement on client change / manual Resume. Provisional-to-canonical key promotion (`migrate(from:to:)`) preserves the single live terminal in place.

## Stopped-session resume relocation and foreground/reconnect freeze fix (owner reports, 2026-11-26)

Two owner reports on physical iPhone:
1. Opening a retired/stopped session directly in Agent Terminal mode stayed stuck on `连接中...` while already-hosted sessions opened normally (`antigravity:16962dcc` was retired 26 minutes earlier; host logs confirmed `session.resume` never arrived).
2. Viewing Agent Terminal on iPhone occasionally froze the entire app after switching to background and returning to foreground or during network fluctuations.

- **Root causes:**
  1. `AgentTerminalPane` owned `resumeTask` in view-local `@State` and called `cancelResume()` in `.onDisappear`. On `NavigationSplitView` compact push relocation, `.onDisappear` fired after the relocated view appeared, cancelling `resumeTask` before `session.resume` completed and stranding `AgentTerminalPane` on `连接中...`. In addition, `.notFound`/`.permanent` errors reset `startAttempted = false`, which could loop or strand the waiting indicator instead of showing `terminal.not_running`.
  2. `RemoteClient.teardownSocket(keepSubscriptions: true)` cleared `hostCapabilities = .empty` on every same-host reconnect, causing `SessionDetailView.canShowAgentTerminal` to flip `true -> false -> true`, tearing down `AgentTerminalPane`, mounting `composerStack`, and toggling navigation chrome mid-reconnect.
  3. `ShellTerminalHost.configure` invoked `onBackgroundColorChange?(cachedBg)` synchronously inside `RetainedShellTerminalView.updateUIView`, mutating SwiftUI `@State`/`@Observable` state during a UIKit layout pass.
  4. `RemoteClient.validateCurrentPath()` / `notifyReadyHandlers()` triggered `RemoteTerminalStream.recover()` simultaneously on all up to 16 retained terminals in `MobileTerminalSessions` on every foreground return or network change, flooding `@MainActor` with 1500-line ANSI snapshot resets for hidden off-screen terminals.
- **Adopted fix:**
  - `MobileTerminalSessions` owns per-session auto-resume tasks and state (`resume(_:client:fontSize:force:)`, deduplicated per `(key, client)`), so transient `NavigationSplitView` relocation `.onDisappear` never cancels an in-flight `session.resume`, and `.notFound`/`.permanent` failures retain `startAttempted` so the restart prompt renders. Only session deletion (`close(key)`), host switch (`reset()`), or client replacement cancels in-flight resumes.
  - `RemoteClient.teardownSocket(keepSubscriptions: true)` preserves `hostCapabilities` (and media/input capability flags) across same-host reconnects until `hello` refreshes them, clearing them only on `!keepSubscriptions` / `disconnect()`.
  - `ShellTerminalHost.configure` defers cached background propagation via `DispatchQueue.main.async` and guards `resignFirstResponder()` behind `if isFirstResponder`.
  - `RemoteTerminalStream.recover()` defers eager `terminal.attach` for hidden retained terminals (`hasBeenLive && !isInFront()`), marking `pendingRevealRecover = true` and recovering lazily when the terminal returns to the foreground (`claimSize()` / `updateFit()` while `isInFront()`).
- **Cross-end boundary:** `MacTerminalPane` also retains `startAttempted = true` on `.notFound`/`.permanent` and renders `restartPrompt` when `stream == nil && !session.hosted && !session.live && startAttempted`; `RemoteClient` and `RemoteTerminalStream` fixes are shared by iPhone, iPad, and Mac; CLI TUI has no mobile `NavigationSplitView` or SwiftTerm pool.
