## 重绘工作流（强制）

视觉方向**一旦在方案里锁定**（例如已选定「延续桌面端开发者气质 + 系统原生骨架」），后续执行：

1. **直接改 SwiftUI**，以本文件令牌与结构约定为合同；用模拟器/真机截图验收，不要再用图像模型批量出探索图。
2. 用户打断出图、抱怨连环生成、或说「别出图了」→ **立刻停掉一切图像生成**，转入实现，不得再开下一轮并行出图。
3. 仅当方向仍未拍板、且用户明确要求「先看效果图」时，才做出图；每次最多推进一张屏的一个方向，先给人看过再继续——禁止一上来并行三套列表 × 三套详情。
4. The approved Corral brand identity is the forest-green and warm-yellow cowboy hat with the Floral 04 cream floral background (owner decision, 2026-10-01). Use `iOS/Assets.xcassets/AppIcon.appiconset/AppIcon.png`, synchronized byte-for-byte from the canonical CLI `brand/AppIcon-1024.png`. Preserve the accepted composition, hat geometry and palette; the retired arrow, horse and unicorn designs must not return. The shared brand contract and README derivatives are owned by [Public presentation](https://github.com/corral-dev/corral/blob/main/docs/PUBLIC_PRESENTATION_GUIDE.md). Keep the app master square and opaque; the README owns its separate rounded display image.

## Mac Agent Activity popover (2026-10-07)

Owner decision (2026-10-07, supersedes the same-day inline disclosure): on the Mac, clicking the compact Agent Activity capsule opens the tool details in a native popover anchored to that capsule. The conversation never changes height, so no preceding or following message moves, and the system supplies the open/close motion. The owner rejected the inline version because collapsing required finding its top header or bottom Collapse button, opening and closing shifted the conversation slightly, it had no motion, and the expanded panel looked unfinished.

- Hit region and reflow (owner report 2026-10-10): the entire visible capsule must open its popover, including its center and lower edge; neighboring message text must not intercept it. Changing interface zoom or window width must keep visible conversation text drawn and preserve the reading position, without requiring a scroll to recover. Keep native cross-message selection and the stable conversation hierarchy. Use the public native borderless Button style for the Mac capsule, keep the pressed/open overlay noninteractive, and let native size-change anchors own Mac reflow rather than issuing new explicit latest-message scrolls from geometry callbacks. Invalidate retained native message displays when typography changes. These are compatibility corrections; the original macOS 26 reproduction remains unverified on the current macOS 27.2 host. Native hit probes use the tested view’s superview coordinates. Preserve the native popover and cross-message selection.
- Collapsed state: the existing compact summary capsule (icon, "Agent activity", tool count, trailing chevron) uses a native borderless button. It shows a pressed/open state while its popover is visible and never changes size. Keep its existing neutral label colors: the native button must use the system label tint, so hierarchical secondary/tertiary styles do not inherit the application’s green accent. The owner rejected the green regression in the 2026-10-10 screenshot; fixing the hit area does not authorize a color change.
- Dismissal: clicking anywhere outside the popover or pressing Esc closes it (the system's transient popover behavior). Clicking the capsule again also closes it. No in-content Collapse button.
- Popover content: a fixed readable width and a height that hugs short content up to a cap, scrolling inside beyond that. A short header names the group and its tool count. Each tool is one row (icon, tool name, up to two summary lines) separated by dividers, with its input behind an individual Details disclosure and its output in a code surface. Tool text stays selectable; Details expansion animates inside the popover only.
- Preserve on-demand detail loading with a progress indicator and the existing unavailable-detail error copy.
- Only one popover at a time (system behavior); opening another capsule closes the previous one.
- Placement (owner report 2026-10-08: the popover appeared on one side, collapsed and reopened on another): the popover prefers the capsule's trailing side and has a fixed width, so height changes only grow it vertically around the capsule and never flip it above/below. Its first frame already has the content height (the scroll view's ideal height up to the cap, not a measured-after-open height), and tool bodies start loading when the pointer hovers the capsule so details normally arrive before it opens.

Scope: Mac only. iPhone keeps its large native detail sheet with drag-to-dismiss and an explicit close control (contract below). The TUI shows the hosted runtime terminal and has no matching Corral Agent Activity capsule.

Compatibility acceptance (2026-10-10): the mounted production capsule resolves nine interior hit points to its native NSButton, at 80/100/150% with short and 120-message conversations and widths 420–760 pt. Native text has drawable glyphs after each reflow; the latest message remains visible, selected history remains selected and in view. Real WindowServer captures of the mounted controls show neutral grey despite an inherited green tint; a native button action opens its actual SwiftUI popover. Fixture data/detail services and unlocalized fixture copy do not establish host transport or physical macOS 26 pointer behavior. The host is macOS 27.2; the reported macOS 26 runtime is unavailable. Installed-window acceptance is recorded after delivery. Cross-client inspection: iPhone has its independent sheet/button path and no Mac interface-zoom preference; TUI uses its native runtime terminal and has neither capsule nor client transcript renderer.

Public API basis: SwiftUI [popover(isPresented:attachmentAnchor:arrowEdge:content:)](https://developer.apple.com/documentation/swiftui/view/popover(ispresented:attachmentanchor:arrowedge:content:)), which on macOS presents a transient popover that closes on an outside click ([NSPopover.Behavior.transient](https://developer.apple.com/documentation/appkit/nspopover/behavior/transient)); [DisclosureGroup](https://developer.apple.com/documentation/swiftui/disclosuregroup) for per-tool Details; [ScrollView](https://developer.apple.com/documentation/swiftui/scrollview) for long content.

### Bottom search: fixed trailing icon (2026-10-01)

Owner decision (supersedes the same-day scroll-collapse attempts): the session list's bottom search is always the system's minimized search icon at the bottom right; tapping it expands the system search field. Nothing switches it on scroll.

Why: the owner wanted MindDistill's smooth scroll-down collapse, but Apple only provides that transition for a real tab bar (`TabView` + `.tabBarMinimizeBehavior`). A search-only bottom toolbar has no scroll-minimize API, and switching `.searchToolbarBehavior` between `.automatic` and `.minimize` swaps instantly. Device evidence: on the paired iPhone (iOS 27) the switch showed only the two end states in sequential screenshots even inside a 3-second animation transaction. The owner rejected that jump and rejected restructuring Corral into tabs just for the animation.

Implementation: `.searchable` + `ToolbarSpacer(.flexible, placement: .bottomBar)` + `DefaultToolbarItem(kind: .search, placement: .bottomBar)` + a constant `.searchToolbarBehavior(.minimize)`. No scroll tracking. Rendering, expansion, editing, clear, keyboard placement and material belong to the system; never replace native search to change its look, size or position. Older systems keep their native fallback. The multiline conversation composer is an editor, not tab/search navigation.

Acceptance: on the installed app the icon sits at the bottom right before and after scrolling, tapping it opens the system search field with the keyboard, cancel returns to the icon, and the last row stays reachable above it.

## 会话输入交互（强制，对标常见聊天软件）

覆盖「键盘弹出后对话没跟着上移 / 输入条被键盘挡住 / 连点发送重复发出 / 翻历史时被强行拉回底部 / 输入框上下键翻不出历史消息」。误修风险：只改输入框样式，漏掉键盘避让、贴底跟随和发送互斥。

验收对象是**会话详情里的输入条 + 对话列表**。终端重新上线后，终端页若共用同一条输入，键盘同样不得挡住输入。不要用无键盘的静态预览冒充。

1. **Keyboard and composer ownership (2026-09-11 rewrite)**: use native SwiftUI keyboard safe-area avoidance. `ChatScreen` reserves the composer with `safeAreaInset(edge: .bottom)`; neither the screen nor conversation ignores the keyboard safe area. Do not calculate keyboard height, select a global window, merge notification/guide samples, or add compensating padding. The composer must remain above the software keyboard and below the navigation bar, including multiline text and image previews. Keep the existing native input field, send exclusion, and draft behavior. The user explicitly requested a complete rewrite using mainstream Apple APIs after occlusion, freezing, and status-bar overshoot regressions.
2. **最新内容跟着上移**：用户本来就在看最新一条时，键盘弹出、输入框变高、自己发出新消息、助手新回复到来，最后一条都必须仍在输入条上方可见。不要只把输入条顶上去、对话还停在原处。**自己发出新消息（2026-09-10）**：点发送（或点提问选项）画出本地气泡后，必须**立刻强制贴底并滚到最底部**——即使刚才在翻历史；这是明确的「看我刚发的」动作，不走「翻历史不抢位置」。
3. **翻历史不抢位置**：用户已经向上翻看更早内容时，键盘弹出或**后台**新消息（助手回复、工具卡）**不得**把阅读位置拽回底部。此时在对话区右下角给「回到最新」入口；点了之后恢复贴底跟随。例外见上条「自己发出新消息」。
4. **滑动收键盘**：在对话列表上出现滚动就立刻收起键盘（`scrollDismissesKeyboard(.immediately)`），不要跟手拖动，以免键盘半悬遮挡阅读。
5. **发送互斥**：文字发送、发图、点提问选项，在途中不可再点；发送按钮在空文案**且**无待发图、或发送中为禁用。点发送后输入框与附图预览**立刻清空**并保持键盘，方便连发；有文字时**同时立刻画出自己的气泡**。Outgoing message appearance (owner correction, 2026-10-10): iPhone and Mac use the ordinary user-message text color and full bubble opacity immediately, including while queued or sending; host confirmation must not change brightness. Delivery failures retain the ordinary bubble with the existing cause and explicit Retry below it, as specified in Send failure feedback. 失败仍把原文与未发出的图还原到输入区并显示错误条。不要等远端成功才清空，也不要等助手历史写完才出气泡。助手正式消息到达后按正文去重，禁止两条一样的用户气泡。**本地气泡位置（2026-09-10）**：刚发出的气泡必须插在「发出时已有正式消息」之后、之后到达的助手正式消息之前；禁止把所有本地负序号整段甩到时间线末尾（否则助手先到时会出现「自己先说的话排在助手后面」；退出重进只剩正式序号又看起来正常）。
6. **不要自动弹出键盘（列表点进）**：从会话列表点已有会话进入详情时不要抢焦点；用户点输入框再出键盘。**例外**：新建会话成功直进聊天时必须立刻聚焦输入（见「主界面结构约定」第 9 条）。
7. **输入框高度**：空卡已是两行（上方正文区 + 下方加号/发送）。正文区默认一行，随字数长高，最多约六行后内部滚动，不得把对话区挤没。加号和发送只按 32pt 视觉占高，行下不要再垫空白，与正文之间留一小段空隙（`Space.sm`）。禁止再把空卡拉高去填中间。
8. **发送反馈**：成功点发送给一次轻触反馈；失败走已有错误条，可再给错误触感。
9. **上下键翻历史消息（机主要求，2026-10-06）**：有实体键盘时（Mac、iPhone/iPad 外接键盘），输入框里按 ↑ 依次取出本会话自己发过的消息（与 Your prompts 同一来源、同一过滤，新→旧），按 ↓ 往回翻，翻过最新一条时恢复开始翻之前没写完的草稿。只在光标位于第一行（↑）/最后一行（↓）时接管，否则方向键照常在多行文字里移动光标；取不到光标的平台（iOS 17）只在单行文字或正在显示的历史原文未改动时接管。取出的消息只填进输入框，不自动发送、不动待发附图；发送或换会话后重新从最新一条开始翻。终端界面（TUI 与 Mac 终端视图）里的输入归各助手自己处理，不在此列。
   - 实现与验收（2026-10-06）：逻辑在 `Shared/Core/Conversation/ComposerHistory.swift`（单测 `Tests/ComposerHistoryTests.swift`），按键在 `ComposerBar` 的 `onKeyPress`；Mac 用当前输入框的文字视图判断光标所在可见行（含自动折行），输入法有未上屏的拼音时一律放行。后台窗口收不到 `CGEvent.postToPid` 发来的任何按键，切前台按键又被本仓禁止，所以验收用调试版环境变量 `CORRAL_INSPECT_COMPOSER_KEYS`（如 `draft:a\nb,up,up,down`，每 3 秒一步，经窗口真实按键分发送到选中格子的输入框；正式版没有）。真窗口实测：两行草稿光标在第二行时第一下 ↑ 只移光标，之后依次取出三条历史（含多行长消息），↓ 逐条返回并恢复草稿，未选中的格子不受影响。首发于 Mac 0.3.22 (26) 与 iPhone 1.0.118 (128)；iPhone 外接键盘路径未实测（真机无实体键盘）。
