## 会话列表首屏

- 列表页必须以该开发机上次成功窗口为界面数据源：进页先画出来，再订阅/刷新。没有快照才转圈。刷新失败且本地有行时保留画面。
- 向开发机带上次版本；回包声明未变则不得把会话数组当成空表覆盖。版本对不上才整窗替换并回写快照。
- 搜索走开发机按关键词查询（可命中窗口外的闲置会话）；不要为了找旧会话在首屏把整表拉下来，也不要在没有新证据时加滚动分页。搜索命中只更新当前筛选画面，**禁止写回该开发机落盘的列表窗口**。
- 切开发机必须换该机快照，禁止把上一台的行留在这一台。
- 用户随口说的滚动分页、再砍字段、完整离线队列不是待办；列表体感慢先对「进页是否空等网络」，对不上就不要堆。

## 对话尾部缓存（重开 / 换网 / 离线）

- 对话详情必须以「该开发机公钥身份 + 规范会话 key」为键的最近成功尾部为界面数据源：再进同一会话先画缓存，再订阅/合并网络更新。禁止先清空再等网络。
- 预算约 50 个最近看过的会话、合计约 100 MiB，按最近访问淘汰；取消配对必须清掉该机全部尾部与未决本地发送身份。
- 缓存是可丢弃的近期上下文，不是完整离线历史，也不是离线命令队列。断线时输入框里的文字保留为草稿；停止/删除等操作不得偷偷排队稍后执行。
- 发送侧在开发机 hello 宣告 `command_receipts` 时使用稳定 `command_id`：本地先落 pending 气泡，再发一次；重连后用 `command.status` 核对未决身份。回执为 `unknown` 时标成需人工确认，**禁止自动重发**。未宣告该能力时保持旧行为，不得假装有持久送达保证。
- 契约见 `https://github.com/corral-dev/corral/blob/main/docs/design/MOBILE_REMOTE_DATA_PLANE_DESIGN.md` §7.2 / §7.6。

## Identity and asynchronous result safety

- A connection belongs to the host captured when that connection was created. Selecting another host must not relabel the active connection; only a successful connection to that host may update its identity. Returning from an obsolete connect, pairing, foreground probe, or local upgrade must not change the current connection presentation.
- Reusing a list store for another host resets the previous host's records, redirects, search membership, version and revision before loading the new host's snapshot. An uncached host must never show or persist the previous host's sessions.
- A tool-detail request is bound to its message sequence, history generation and current tool summary. Resolve the message again after the asynchronous call; prepended or evicted history can invalidate an array index. Reject a response from an obsolete generation, stopped view, or changed tool summary. Duplicate tool identities in a response must not crash the app.
- A known replacement history generation invalidates the previous official messages and cursor, even when the replacement tail is empty or mistakenly marked as replay. Preserve unresolved local sends, but do not display old official history as current. An empty response without a changed generation still retains usable cached context.
- Two outgoing messages with different command identities remain two messages even if their text is identical. Only the same command identity may reuse a local bubble; text equality is a legacy presentation fallback, never a receipt identity.
- A stopped conversation view rejects late events, prompt refreshes and question submissions; a replaced question request never updates the submission state.
- A notification open is owned solely by PushRegistrar's `PendingNotificationOpen` (`Shared/Core/Network/NotificationReply.swift`): the paired host+session identity survives connection waits with no duplicate state. No message is synthesized from the tap.

### Native Mac lifecycle requirements (2026-10-05)

- Switching hosts resets the Mac workspace's layout revision, panes, focus, board, expanded prompts and runtime catalog. Persisted panes and view modes belong to a host, not just a session key. Late layout, runtime and action responses from a replaced host/client must not alter the current workspace.
- A terminal pane reattaches on a recovered connection, discards stale stream sequence state and waits for a fresh snapshot. Stopping a pane invalidates outstanding attach, resize and resync work; an attach that succeeds after stop must release its host subscription and sizing vote without detaching a newer attachment.
- A terminal sizing vote becomes acknowledged only after a successful host response. Transient failures retry the latest desired grid; stale or cancelled responses never acknowledge a newer fit.
- Full-text search binds successes, failures and loading cleanup to the current request and client. Editing or clearing the query, changing client or dismissing search invalidates older work immediately, including an identical query entered again. A recovered connection reruns the current query; transient read-only failures retry within a bounded budget.

These rules follow Swift's actor reentrancy: state can change across `await`, and cancellation is cooperative. See [Swift concurrency](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/concurrency/) and [Apple Task cancellation](https://developer.apple.com/documentation/swift/task/cancel()). Deterministic regressions cover host switching, delayed detail replies, replaced history and repeated text; physical-device interaction is a separate acceptance layer.

## 高频事件处理

- 会话实时消息先合并进本地列表，再以短暂合并窗口刷新服务端的提问选项；禁止每收到一条消息就额外发一次提问选项请求。服务端会批量推送增量，逐条再请求会与输入、画面更新争抢同一条连接。
- 合并消息时按稳定序号去重后统一排序，禁止对服务端一批消息逐条插入并逐条排序。序号重复必须后到覆盖先到，禁止用「键必须唯一」的建表方式——重复键会直接闪退。本地负序号气泡按发出时的最新正式序号锚定插入（`localAfterSeq`），禁止「全部正式在前、全部本地在后」——助手正式回复先到时会把用户刚发的话甩到末尾；退出重进只剩正式消息时顺序又正常，正是这一症状。
- 对话气泡 Markdown 必须走有上限与缓存的解析（`ChatMarkdown`）：完整语法（含标题/列表/表格）仍在有界同步路径上完成，并缓存结果；禁止在 `body` 里对任意长度正文反复同步 `AttributedString(markdown:)`，也禁止为「更全语法」引入第三方库却仍无上限。超长正文改纯文本；否则场景刷新会卡满主线程，触发 `0x8BADF00D` watchdog 杀进程。
- 终端画布的默认背景只画一次；默认空白格不创建文本布局或背景填充。带背景、反色、下划线或真实字符的格子仍须完整绘制，不能以性能名义丢失终端语义。

## Main-thread budget (2026-10-05)

### Split sidebar resizing (owner report, 2026-10-10)

Continuous sidebar-width changes in the Mac split workspace must keep the native divider responsive while the adjacent conversations reflow. Preserve opened panes, native text selection, scroll position, drafts and the equal-width pane contract. Verify short and long loaded conversations with multiple panes; an isolated build or one settled resize does not establish interactive performance. Use the existing native `NavigationSplitView` and AppKit text network rather than replacing the divider or rasterizing conversation content. Inspection must not drive the user's pointer. iPhone has no resizable split sidebar; compare the TUI's independently owned sidebar sizing path for the same unnecessary repeated work.

The native divider probe reproduces expensive chat realization and text layout during continuous sizing. Initial optimized-build measurements for 120 loaded messages: two panes had a 168.5 ms median and 423.9 ms maximum per step; four panes had a 34.5 ms median and 101.4 ms maximum. These are fixture measurements, not visible display-frame timings. Adopt a fixed equal-slot layout through Apple's public [Layout](https://developer.apple.com/documentation/swiftui/layout) protocol so the product split supplies the known width and height directly, without general-purpose horizontal-stack flexibility probing. The existing pane separators, native controls and render-time entrance/exit effects remain. API presence and macOS applicability were checked in the installed Xcode 27.2 SDK; compare the same fixture before accepting the change.

Paired layout-only runs did not establish a material performance improvement. The remaining measurement path recreated an attributed text storage, layout manager and text container at every new width. Keep a detached TextKit 1 measurement network and a bounded width-size cache for each recently measured message; replace its attributed source only when that source changes and change only container width during reflow. Lazy row reattachment must reuse these measurements from its conversation document instead of starting again. Retain at most 32 measured messages per conversation and 64 widths per measurement; remove vanished messages and clear on conversation replacement. Standalone text uses its row coordinator. This preserves glyph caches without measuring through the live selection network or retaining an unbounded history cache; text/style changes still invalidate cached sizes. A repeated four-pane sample localized the remaining work to detached `ensureLayout`, so validate this bounded reuse against the same native-divider fixture before claiming a gain.

Sampling also identified repeated `NSTextView.isSelectable` assignments during lazy-row realization as an expensive shared-network layout path. After guarding that setter, a second sample identified `drawsBackground` as the next redundant setter forcing the same layout. Apple's [multiple-text-view contract](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/TextUILayer/Tasks/MultipleViews.html) says selectability, editability and rich-text mode are shared across a layout manager's views. Reattaching a document-owned view must check the current value before setting these attributes and unchanged native geometry/style flags. Keep the native text network and its selection; do not disconnect containers or suppress drawing to hide the work. These bounded guards are separate from the already integrated activity/zoom corrections. Uncapped Mac message rows also skip edge-fade backing-layer setup from native layout/scroll callbacks: they have no hidden tail and need no mask. Retain the native capped-row fade behavior when a vertical scroller is actually enabled.

Resize verification (2026-10-10): production text/scroll views in the native divider fixture, 60 steps per case, 120 loaded messages: with bounded document-owned measurements, two panes measured 25.7 ms median / 50.7 ms p95 / 56.5 ms maximum; four panes measured 29.3 / 46.0 / 60.5 ms. The preceding coordinator-only four-pane run was 30.0 / 202.9 / 205.7 ms. The main improvement is reuse across lazy row lifetimes, not the equal-slot layout alone. Five inspected window captures across the four-pane sweep retained drawn text and equal pane widths. Detached cache tests cover source/width invalidation, reuse, eviction, removed history and pane isolation; native selection/copy/history/streaming/zoom probes passed.

Recheck (2026-10-11, production direct native rows, 60 divider steps per case): 120-message two/four-pane medians were 22.98/22.75 ms, p95 46.36/46.35 ms and maxima 54.93/60.56 ms. Three-message two/four-pane medians were 8.11/9.47 ms, versus the previous short two-pane run near 82 ms. These are layout-step timings, not display-frame guarantees; new captures were unavailable on the locked console. The preceding fade-only change had not reduced short-case glyph-rasterization cost. Do not report a universal frame-rate guarantee or a complete removal of drag/scroll latency from the long-history gains. Capture scenarios are separate from the unpaced timing run. The iPhone has no adjustable split sidebar and does not use the Mac TextKit network; TUI uses its separate fixed sidebar and debounced terminal repaint path, with no copied native setter/measurement defect.

### Mac sidebar switching requirement (2026-10-10)

Switching a session from the native sidebar must update selection immediately. The owner specifically prioritizes split-session switching and requires nearly imperceptible millisecond-scale performance. The investigation's engineering target is the next display frame on recently used single/two/four-pane workspaces; a 50 ms main-thread pause or 100 ms warm content delay is a failure to investigate, not an owner-specified numeric requirement or an achieved result. Returning to recently viewed sessions must avoid repeated synchronous disk decoding and rebuilding equivalent conversation state. Keep caches bounded and host/client-scoped; never retain hidden terminal sizing votes, active subscriptions, first responders or inaccessible controls. Cold uncached history may still depend on the host, but must not block selection or input. Measure the actual workspace opening path and native window layout separately from RPC time; successful builds and isolated cache timings are not whole-window acceptance.

**Status (2026-10-11 evening, owner handed the task over after earlier attempts stopped): measured improvement, goal not yet achieved.** Whole-window attribution (DEBUG timers on pane hosting views, table and window layout; Release+DEBUG profile, sampling kept separate) showed that row rendering was never the bottleneck: warm switches evaluated ~30 SwiftUI bodies and 0 rows, while ~80% of the pause was window layout. Two causes were removed in Mac 0.3.74: (1) SwiftUI `allowsHitTesting`/`accessibilityHidden` toggles on retained panes made every switch re-insert each mounted `NSHostingView`, and `AppKitPlatformViewHost.viewDidMoveToSuperview` → `_setDefaultKeyViewLoop` forced a synchronous subtree layout per insertion; dormant exclusion now stays native (`isHidden`, `Mount.hitTest` returning nil). (2) Hidden dormant hosts were still laid out on every switch; `MacPaneHostingView` defers layout while hidden and lays out once on reveal. Warm main-thread pause medians, profile build, 24 inspected switches: 258/323/392 ms → ~135/150/220 ms (single/two/four). Mac 0.3.75 removed a third cause: `MacRetainedPaneLayout` remembered dormant-pane frames from SwiftUI's degenerate measuring placements (220 × 0), so every pane collapsed as it went dormant and reflowed its whole conversation on return; only non-degenerate placements are remembered now. Medians: ~70/112/162 ms. A fourth cause followed: SwiftUI writes `false` back into every presentation binding (`alert`, `confirmationDialog`) when the root re-renders, and the root's bindings cleared already-empty observable values (`MacWorkspace.actionError`, `pendingTerminalClose`, `MacNotifications.failure`); Observation notifies on equal writes, so each switch paid an extra update pass. Setters now write only on change. Mac 0.3.76 returned to the shared lazy conversation (pooled table withdrawn, see the table below) with no speed loss: ~64/99/170 ms. The remaining single-pane time is spread over about 30 small SwiftUI transactions per switch; the largest are the workspace mutation itself (~16 ms in two passes) and four separate `MacPaneLifetime` presentation/focus mutations (~17 ms). Coalescing those is the next lever. The 50 ms pause budget is still unmet; do not call any shipped version imperceptible switching. Feel-only tricks stay vetoed.

Switching profiling method (2026-10-11, reproducible): build Release with the inspection hooks, `xcodebuild -scheme CorralMac -configuration Release -derivedDataPath .derivedData-mac-profile SWIFT_ACTIVE_COMPILATION_CONDITIONS='$(inherited) DEBUG CORRAL_DIRECT_DOWNLOAD' build`, quit every Corral GUI process, launch it with `-CorralInspectSessionSwitch -CorralInspectSessionSwitchNoForce`, and read warm (`cycle > 0`) `maxMainStallMs` medians from `/tmp/corral-mac-session-switch.json`; run twice, because medians move about 10 ms between runs. For attribution, record Instruments' SwiftUI template by process (`xcrun xctrace record --template SwiftUI --attach <pid>`); `--launch` with a path fails as ambiguous while several Corral copies are installed. Export only the `swiftui-update-groups` table (about 20 MB, rows carry a cause backtrace naming the Corral mutation); the full `swiftui-updates` table exceeds 5 GB. Clustering its transactions by time gap gives one timeline per switch. Temporary `print` or stack-trace instrumentation must be removed before timing, because it inflated pauses by more than 100%. For window captures with `-CorralInspectConversation` and `CORRAL_INSPECTION_SESSION_KEY`, pick a session in chat mode: pane modes persist per session in the shared `corral.mac.paneModes` user default, so a session last shown as a terminal opens as a terminal. Scrolling feel and pointer interaction stay with the owner (no pointer automation).

Unlocked follow-up: the same optimized profile measured 195/363/547 ms warm medians with zero warm preparation, document renders, timeline rebuilds or prompt recomputes. Another task's Debug GUI was present, so this is diagnostic reproduction, not isolated final acceptance or a causal percentage comparison. A separate sampled run points chiefly to `NSHostingView.layout` / SwiftUI DisplayList and AttributeGraph updates; native glyph drawing is a smaller sampled branch. Keep timing runs separate from sampling and captures. Research exemption: these are private product measurements; existing public native APIs remain unchanged.

Retained-mount correction to evaluate: the native host already owns hidden visibility, focus retirement and input exclusion. Avoid applying a second SwiftUI opacity change to the complete retained subtree. Keep its internal roster order stable across warm workspace changes, and preserve each dormant slot's previous position as well as size. Visible pane order still follows the user's workspace keys. Keep native `isHidden` (including keyboard navigation, tooltips and tracking), watch suspension, accessibility exclusion, client scope and bounded eviction; transparent native views are not a substitute for hidden views. Verify native geometry and actual whole-window timing before reporting a gain.

Corral owns native presentation, hosting, derived caches and read/watch policy; SessKit history interpretation is unchanged. Keep at most four eligible dormant native chat hosts plus visible panes. Preserve measured hidden geometry, exact native scroll/composer state and text selection. Equivalent visible session/environment inputs do not reassign `NSHostingView.rootView`; hidden hosts receive no root reassignment, watches or focus. The hosting boundary uses Apple's public [NSHostingView](https://developer.apple.com/documentation/swiftui/nshostingview) and [sizingOptions](https://developer.apple.com/documentation/swiftui/nshostingview/sizingoptions), verified in the installed SDK. Client replacement and host reset release old ownership; terminals and oversized histories are excluded from retention. A native mount publishes window coordinates because a separate hosting view has a different SwiftUI global space.

Presentation/watch observation stays in a small lifecycle view, outside the expensive chat layout. The mount updates focus/peer state only in presented panes; dormant panes do not observe unrelated workspace focus. Preserve cancellation, pending-unwatch ordering, current-client replacement and read acknowledgements. Warm pane/detail construction seeds the current-client store and last body size, avoiding an initial nil-store layout; this did not by itself establish a timing gain. The teardown/message-center restore draft was superseded: it cannot preserve an exact reading offset, so the retained native scroll state remains authoritative.

Projection-cache correctness: sequence identities alone do not establish unchanged text, role or origin. Invalidate cached human prompts on loaded/fork history or host-prompt changes; cache bookkeeping must not send Observation notifications. Regression `testPromptCacheUpdatesWhenTextOrRoleChangesAtSameSequence` fails before the fix for corrected text and changed role and passes afterwards. Equal snapshots retain the fast path. Native link/selection drawing attributes also guard equivalent values using Apple's [linkTextAttributes](https://developer.apple.com/documentation/appkit/nstextview/linktextattributes) and [selectedTextAttributes](https://developer.apple.com/documentation/appkit/nstextview/selectedtextattributes); this bounded no-op guard did not resolve switching latency. Diagnostics counters are MainActor-isolated and compile out of Release.

Affected source and probes: [MacPaneSurface](../macOS/Panes/MacPaneSurface.swift), [MacPaneView](../macOS/Panes/MacPaneView.swift), [MacSplitArea](../macOS/Panes/MacSplitArea.swift), [native selectable text](../Shared/UI/Chat/SelectableAttributedText.swift), [whole-window switch inspection](../macOS/MacSessionSwitchInspection.swift) and [native cache/geometry probe](../scripts/test_mac_session_switch.py).

### Shared processing budget

Every frame is ~8 ms at 120 Hz. Work that scales with payload size must not run on the main actor; the main actor only applies already-decoded values.

- **Approachable concurrency moves "background" code onto the caller.** The project sets `SWIFT_APPROACHABLE_CONCURRENCY` (SE-0461 `NonisolatedNonsendingByDefault`): a plain `nonisolated async` function runs on the caller's actor. Anything that must leave the main actor is marked `@concurrent` — the frame pump (`PlaneIO.pump`: receive, decrypt, inflate, JSON parse) and typed RPC decoding (`RemoteJSONDecoder.decodeOffMain`, used by `RemoteClient.call(_:params:as:)`). Before 2026-10-05 the pump's "not on the main actor" comment was false. The SPM package does not enable this feature, so SPM tests cannot catch a regression; build the Xcode targets.
- Wire models decoded off the main actor are declared `nonisolated` (otherwise their `Decodable` conformance is main-actor isolated and cannot cross executors). New response types follow the same rule.
- Flexible decoding helpers short-circuit an absent or null key to the default instead of cascading four failed `try?` decodes; the cascade was the dominant decode cost.
- The conversation tail cache encodes and writes on a serial background queue, coalescing bursts per session; `load` sees the newest pending snapshot first, and host removal cancels pending writes before deleting files.
- Measured on real host payloads (Apple-silicon Mac, release build; iPhone is slower): an 80-message history page cost ~6 ms of main-thread decode, the 80-row list ~3.4 ms, a 400-message cached tail ~8 ms to load and ~3.7 ms to save per event batch. Reproduce with real `session.watch` pages before claiming a regression or a win.
- Other bounded main-thread work: list rows and the prompts list reuse cached `DateFormatter`s (building one per row cost ~50 µs; 80 rows 3.9 ms → 0.08 ms); full-list `sessions` pushes decode off the main actor in `HostSessionFeed` and re-check host/client ownership afterwards; the iPhone selectable bubble caches its converted `NSAttributedString` and per-width measurement like the Mac one and queues a scroll-mode update only when the mode changes; `ChatMarkdown.prewarm()` pays the first-parse setup (~15 ms, plus ~15 ms for the first block quote) on a background thread at launch.

### List working-set and persistence requirements (2026-10-07)

- Shared native list metadata belongs to the current host window, current search results and currently opened details. Replacing a window/search or closing a detail releases records no longer owned by any of these surfaces; keep migration aliases only while their canonical identity remains owned. Do not accumulate every previously searched session for the lifetime of the client.
- List-cache serialization and atomic writes run on a serial utility queue, coalescing event bursts per host. Save-then-load returns the latest accepted snapshot, including while a write is in flight. Unpairing cancels pending work and deletes after older writes finish, so a late write cannot resurrect the host cache. These are disposable list snapshots, never user content or a command queue.
- Profile the installed Mac separately from inspection processes. CPU deltas must be measured without an attached sampler; physical footprint and retained metadata ownership are distinct from RSS. Concurrent inspection clients can exceed the paired-device channel budget and cause reconnect churn; do not attribute that churn to idle production CPU.

## Connection recovery requirements (2026-10-05)

Approved after the connection-design review. Applies to the shared iPhone/Mac connection layer; the local TUI has no client transport.

- A transport handshake is not application readiness. Publish Connected only after an authenticated host hello confirms the pairing; a revoked pairing reports a recoverable pairing error, never a false green state. Reconnect readiness and subscription restoration obey the same boundary.
- Transient initial connection/hello failures recover automatically with bounded, jittered backoff. Invalid identity or revoked pairing stops automatic retries; preserve pairing records and cached content.
- Discover matching host addresses concurrently with connection attempts, never as a blocking preflight. Failed races refresh discovery. Bound each race, rotate through remaining candidates, and retain fresh candidates rather than permanently truncating the set to three.
- Network changes and foreground/wake events first validate an existing usable control connection. A healthy path stays open. Failed paths re-race LAN and the configured relay; no network-type gate and no shared relay default. Suppressed startup changes are checked after connection confirmation.
- A missing data plane retries with a capped low-frequency delay for as long as its confirmed control plane remains available; foreground/wake accelerates that recovery. Only acknowledged data bindings route history/terminal requests to that plane.
- iPhone and Mac use the same foreground recovery entry. Changing the direct-connection preference updates the current client's next attempts immediately.

Use Apple [NWPathMonitor](https://developer.apple.com/documentation/network/nwpathmonitor/) as a change observer and [URLSessionWebSocketTask](https://developer.apple.com/documentation/foundation/urlsessionwebsockettask) for the existing transport. Connectivity is established by real requests, not interface labels. Verify source regressions with controlled fault injection and the real encrypted host path separately from physical Wi-Fi/cellular and sleep/wake acceptance.

## 连接层审查清单

- 发出请求前必须先登记响应接收者；反过来会让低延迟响应先到、被接收循环当作无主响应丢弃，随后用户等到超时。发送失败时必须撤销该登记并立即唤醒等待者。
- WebSocket 探活 `sendPing` 的完成回调在断线竞态下可能触发不止一次；桥进 `CheckedContinuation` 时必须一次性门闩，禁止直接二次 `resume`（会断言闪退）。见故障排查「探活 double-resume」。
- 局域网与中继继续并发抢答；每次重连与网络切换必须重新选路，不能复用上次的具体地址。第二条数据面连接用同一套抢答，禁止复用第一条胜出的具体地址。
- **Deterministic handshake-test ordering**: `HandshakeArbiter.launch` returns a discardable task handle so a test can await completion after that attempt's `offer`/`fail` call. Production callers ignore it; locking and cancellation remain unchanged. A nil handle means the arbiter was already settled and no attempt was registered. Register both attempts before releasing the first, then await its handle in the second. A fixed sleep cannot establish completion order under full-suite scheduling load.
- **抢答超时不得变成长连接寿命**：`ConnectCandidate.timeout`（局域网 2 秒 / 中继 8 秒）只给握手竞速用。已建立的 `URLSession` 禁止把 `timeoutIntervalForResource` / `timeoutIntervalForRequest` 设成这个值，否则空闲对话几秒到几分钟后会在手机仍显示「已连接」时悄悄死掉。长连接配置：资源超时无限、请求超时 7 天，探活约 15 秒 ping 一次，约 45 秒无收包判定该平面失败。
- **连上验收**：装上/启动、局域网 TCP `ESTABLISHED`、把 Connecting 改成 Failed，都不算连上。必须状态条已连接，且 `corral remote status` 当前在线 ≥ 1。2026-09-13 构建 55 未过这条时用户裁定停手，禁止再加超时/闸门补丁（见远程知识库该踩坑）。
- 手机必须主动探活（WebSocket ping 或应用层心跳），并记录最近一次收到开发机数据的时间；超过约 45 秒无收包即判定断线并重连。回到前台时若已超过空闲阈值，禁止因为状态仍是 ready 就直接 return。
- 数据面断开必须持续自动重新绑定（延迟封顶，回前台加速）；绑定失败要能被观测到，不能 `try?` 吞掉。控制面断开才算设备离线。
- 重连成功后，列表、对话、终端各自重新登记服务端订阅，但保留已有界面内容直到新快照有效，避免闪空。
- 对话重连必须带上已应用到的最后序号和历史代次。开发机回包声明只补缺口时，把新消息合并进现有列表，禁止整表替换；空的补缺口回包表示没有新内容，不是清空。序号对不上或历史代次变了才重新取当前尾部；尾部为空且本地已有内容时不得闪空。终端画面仍只保留最新帧，不按序号回放。
- 新客户端在控制面握手成功后，若 hello 带回绑定令牌，再开第二条 WebSocket 承载历史页和终端帧。旧客户端或旧开发机没有该令牌时必须仍能只用一条连接。收包的解密、解压和 JSON 解码不得堵在界面刷新路径上。
- 数据面断开时控制面保持，允许重新绑定；控制面断开才算设备离线。

iOS **1.0.14**（构建号 15）对应提问选项按题分组、过期问卷从输入条上方收掉。前一版 **1.0.13**（构建号 14）是长连接保活、发送立刻出气泡、助手「正在处理」。开发机侧 CLI **0.24.157**。真机装上后须点一次：两道选择题是两组而不是一排 8 个按钮；对话继续后旧问卷消失。

### 实现与验收（2026-09-10 已修）
